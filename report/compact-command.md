Compact command and context display

Selecting the Compact action now executes it immediately, with the same behavior on Enter. Tab still completes the name. Sending typed /compact remains supported, including before the command listing arrives or when that listing fails. The composer clears the command and persisted draft at dispatch, retains attachments, and preserves words typed while compaction runs.

The timeout was a real client deadline, not evidence that the backend stopped. The compaction POST awaits the model summary and flushed record before replying. Its route and Flue coordinator do not receive the HTTP request's abort signal. In the desktop transport, JS abort only stops waiting for the Tauri invoke: Rust service_fetch continues, bounded by 165 seconds. The old 12-second deadline therefore cleared the compacting flag and triggered a transcript refresh while the backend could still be summarizing.

The compaction POST now uses the same 150-second long-operation budget as the existing media routes, below the desktop seam's limit. Ordinary requests retain their 12-second deadline. Network refusals and genuine 404/409 responses remain errors. A long-operation deadline produces a compaction-specific warning that work may still be running; it does not claim the harness died or automatically retry. Compaction remains a bounded synchronous request, not a background job that can be tracked indefinitely after a timeout.

The other mechanisms are separate: SSE sends heartbeats every 15 seconds, with 45-second idle/liveness budgets. The native stream has a 10-second connection budget. Pairing/status-route 404s can identify an ordinary development server rather than Studio's listener; a real API 404 is still reported. No five-second health timeout was found in the compaction path. Five-second bounds elsewhere include shutdown acknowledgments, MCP startup, and storage waits; this change does not suppress their failures. The user's unspecified earlier five-second/404 cases were not reproduced independently.

After compaction, the harness writes an estimated context record based on the summary plus fixed 8,000-token tail and 12,000-token prompt allowances. The later provider measurement can therefore differ from the provisional figure. The context menu now says Awaiting next turn and hides the provisional count, fill bar, free count, and trigger percentage until measured usage arrives. The context-accounting algorithm is unchanged.

Changed files: Composer.tsx and useSlashCommands.ts handle action execution and immediate clearing; useCompactNow.ts provides the operation-specific timeout sentence; client/request.ts and client/conversations.ts carry the per-operation deadline; ContextTank.tsx and TurnMenu.tsx distinguish unmeasured compacted context. Their composer, client, transport, and context tests cover the behavior.
